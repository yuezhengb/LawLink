# LawLink 内部经营财务操作说明

## 这套工作区解决什么问题

内部经营财务工作区用于把律所自己的来源资料、人工认领、分成规则、个人内账和月结交付串成一条可回看的记录链。它服务于律所内部核对和管理，不替代法定会计账簿、纳税申报或外部财务老师的最终口径。

原有的案件应收、收款分配、开票和案件财务明细仍在原入口使用；内部经营财务入口只新增一条独立工作线，不改变案件级统计语义。

## 入口与权限

- `/finance`：原有案件财务入口。页面有“内部经营财务工作区”入口卡片时，当前账号具备内部财务查看权限。
- `/finance/internal`：内部财务总览，显示当前账期的来源文件、待认领、正式批次和月结闸门。
- `/finance/internal/imports`：银行流水与财务资料导入、预览、归档和受保护下载。
- `/finance/internal/reconciliation`：待认领与归类队列，以及决定表导出。
- `/finance/internal/ledger`：人员内账、客户项目归属、律所经营成果和导出。
- `/finance/internal/rules`：规则草稿、版本、生效日期和发布状态。它属于“分成与个人内账”这一组。
- `/finance/internal/monthly-close`：月结阻断项、正式批次、追加调整、冲销和交付包。

内置“财务”账号可以执行全所内部财务动作。自定义角色必须获得对应的明确权限；普通律师不会因为能查看案件财务，就自动进入内部经营财务工作区。

## 推荐操作顺序

### 1. 导入并归档来源

在“银行流水与归档”中先选择资料类型，再选择文件并预览。支持：

- CSV；
- XLSX；
- 工资表、花名册、外账三表等作为归档来源。

传统 XLS 会被明确拒绝，请先转换为 XLSX。单个文件上限为 25 MB。预览阶段不写入数据库；提交时会重新解析并校验，任何错误行都会阻止提交，不会静默丢行。

系统会保留原文件的 SHA-256 指纹、归档元数据和银行来源行指纹。工资表、花名册和外部三表保存为待人工复核的类型化记录，不会制造银行流水或待认领案件；工资姓名与花名册姓名只留在受保护的原始文件中，不写入数据库，也不存可枚举的姓名摘要。相同文件和资料类型再次提交时返回原批次，不重复写入。

月结前需按账期确认银行账户/流水批次、工资、花名册和外部三表覆盖。已选外部三表批次还会核对是否包含资产负债表、利润表和现金流量表；缺少的表会显示为复核提示，并标明会计资料包不完整。

工资、花名册和外部三表会进入“人工复核”列表。财务人员按原文件名、来源批次和行号查看受保护原件，再手动选择在职人员；同名人员不自动合并，花名册关联也不会修改用户档案。确认工资行会把申报工资、实付和个人自担金额登记为工资事实，同时明确保留“工资承担口径待复核”状态；律所承担工资、社保、公积金等数据补全并由财务确认前，系统不会把该事实当作已完成工资核对，也不会放行月结。外部三表只登记人工核对状态，不会改写案件收入或律所事实。

### 2. 处理认领与归类

系统只从“已确认的律师费收款”中找候选付款，不会把待确认实收、代收、代垫或其他金额自动认领为律师费。

建议排序规则如下：

1. 金额相同，且外部流水号或发票号一致：100 分；
2. 金额相同，上海日历日一致：90 分；
3. 金额相同，日期相差不超过 3 天：70 分；
4. 金额不一致、日期超出范围或候选付款已经被其他来源行确认：不提供建议。

同分候选不会自动确认。人工决定有四种业务结果：接受建议、改选目标、标记疑点、忽略并说明。确认、忽略和疑点都会追加决定记录，原来源行不被改写。

需要处理退款时，先在原收款账登记并确认退款冲销，再到本期对账队列将银行支出行关联到原律师费付款。关联金额必须等于该银行退款行金额，且累计有效关联不得超过原付款已登记的退款金额；一条来源退款行只能关联一次。关联会将来源行标为已确认，退款进入退款发生期的分配快照，并按原付款最近有效正式快照的各方比例冲回；找不到原快照、金额不守恒或退款账面余额不足时，系统阻断而不估算。退款关联及冲销构成来源指纹的一部分，预览后发生变化必须重新计算。

### 3. 维护规则并生成正式分配

规则先保存为草稿，再按生效日期发布。已发布版本不可修改或删除；同一规则集的生效日期不能重叠。比例使用小数填写，例如 `0.10` 表示 10%。

渠道、律所和案源/承办/协办的计算使用 Decimal，不用浮点数。案源、承办、协办比例必须合计为 1；最后一项吸收分币尾差，保证分配金额守恒。

案件财务画像记录来源类型、参与人员、渠道标签和生效规则集。正式分配只读取：

- 已确认的律师费付款；
- 已生效的案件财务画像；
- 有效分成方案；
- 收款日适用的已发布规则；
- 有效退款链接。

正式提交前会重新读取这些事实并比较来源指纹。来源发生变化时，旧预览不能提交，必须重新预览。正式批次是不可变快照；相同来源指纹会复用批次，变化后追加新批次并把旧批次标记为已替代。

### 4. 查看人员、项目和律所结果

“分成与个人内账”使用同一个正式批次展示三个视角：

- 人员：总收入、渠道、律所、案源、承办、协办，以及有内账事实时的可分配余额、预存保障和保障缺口；
- 项目：分开显示案件标的额、现行有效签约律师费、累计已开票净额、累计确认净收款和本期分配净额（含退款）；付款行另标来源类型、发生日期和退款关联。案件标的额不等同于合同收费，开票不等同于到账，客户引用在导出中保持掩码；
- 律所：律师费收入、渠道、律所留存、律师分配和经营成果。

个人双余额中，预存保障用于观察两个月自担成本的覆盖情况；保障缺口允许跨月结转，不会被强行截为零。收入提取、合伙人税款预付和资本流不重复进入律所经营成果；资本流只作为资本事实记录。

### 5. 月结、调整和交付

月结闸门会检查来源覆盖、待认领、正式分配批次、分配异常、工资事实和复核提示。存在阻断项时不能生成正式月结包。

月结交付只允许基于 `COMMITTED` 正式批次生成，并把交付文件、计算批次 ID、来源指纹、文件 SHA-256 和审计记录绑定在一起。当前交付包含：工资工作簿、会计资料工作簿、个人内账工作簿、调整审计工作簿和完整 ZIP 包。重复点击会复用同一批次已有的完整交付记录。

月结调整采用追加凭证：新调整记录有科目、金额、理由和证据引用；冲销会追加等额反向记录并保留原凭证及 `reversalOfId`，不会删除或覆盖原始银行行、工资事实或分配行。

交付文件下载需要登录、内部财务查看权限和正式批次状态；下载本身写入严格审计。来源文件下载同样需要权限并写入审计。

## 数据边界与上线前检查

- 合成测试只使用 `synthetic-*` 标识，不连接生产数据库，不使用真实客户名称、合同号、银行账号或密码。
- 原始来源文件应使用受保护存储；不要把来源文件、脱敏前流水或导出交付包提交到 Git。
- 数据库迁移应先在独立测试数据库演练，再由负责人确认后应用；未完成迁移前不要把入口指向生产数据。
- 外部财务老师核对时，建议先选一个脱敏账期，对照来源行、认领结果、退款、分配比例、个人双余额、税款预付、资本流和月结交付包逐项确认。
- 该工作区的输出是经营管理核对结果，不是法定财务报表。发现口径差异时，以来源证据、已发布规则版本和审计链为准，不能直接改历史记录。
