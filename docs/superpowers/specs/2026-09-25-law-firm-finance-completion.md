# 律所财务真实资料导入与工作区补全设计

**日期：** 2026-09-25  
**状态：** 用户已批准（2026-09-25）
**目标环境：** 170 预览环境；101 仅作只读参照

## 1. 目标

在现有 LawLink 律所财务域上完成两件事：

1. 让已提供的银行流水、工资表、花名册、外部财务三表、案件登记资料及 PDF/传统 XLS 来源进入正确、可追溯、可人工复核的结构化流程。
2. 补齐律师个人结算包、往来单位流水分析、资金经营总览和财务企微摘要推送，使财务人员能从导入、核对一直走到月结交付。

本项目是律所内部经营核对工具，不替代法定会计账簿、纳税申报或外部财务老师的会计判断。

## 2. 已知基础与设计约束

- 现有系统已经具备 CSV/XLSX 导入、文件指纹、受控原件存储、审计、银行对账认领、正式计算批次、个人/项目/律所报表和月结导出。继续复用这些服务和权限，不另建第二套账。
- 现有类型化导入支持银行流水、工资、花名册、外部三表，但需要针对真实表格的列名、日期、账期与行布局补充映射/解析；“原件已归档”不能记作“业务数据已导入”。
- 此前兼容性检查中无法结构化识别的资料已作为 OTHER 原件留档。后续成功结构化时新增类型化批次，保留旧批次、原件与审计记录，不覆盖、不伪装为已确认事实。
- 与 101 的功能差距依据 2026-09-24 的只读代码/页面结构核对；此核对不是 101 当前线上端到端验收。101 不进行代码、数据库或配置变更。
- 客户、案件、员工、银行及工资资料不得写入 Git、测试夹具、普通日志或公开地址；OCR/转换不调用外部 AI、云 OCR 或第三方上传服务。
- 真实资料的最终导入须经系统预览、字段/期间确认与审计；测试使用合成样本，不把真实值加入自动化测试。

## 3. 资料导入流程

### 3.1 通用流程

`上传原件 → 私有存储与 SHA-256 指纹 → 识别/映射预览 → 财务人员确认类型和期间 → 事务化写入待复核批次 → 页面逐行复核 → 原有认领/结算流程`

- 每种来源按 `(文件 SHA-256, 来源类型)` 去重。相同文件以另一来源类型重新结构化时允许建立新批次，但不能删除此前归档批次。
- 预览显示文件类型、账期/截至日、行数、错误、重复提示及经权限裁剪的样例；有硬错误、金额/日期无法解析或期间不明时不得提交为有效记录。
- 原件保存、来源行/类型化记录、批次状态和审计事件保持原子一致；提交失败不留下半成品业务事实。
- OCR/转换输出只能成为待复核候选。识别置信度不足、页数超限、加密/损坏文件或版式不支持时，明确失败或要求人工处理，不静默跳过。

### 3.2 传统 XLS 与 PDF

- 在同一受控部署内增加隔离的文件预处理工作者，复用开源 LibreOffice 做旧式 XLS 转换，OCRmyPDF 与 Tesseract（简体中文模型）做扫描 PDF 文本提取；开源组件版本及许可证随发布记录。
- 工作者仅在内部容器网络可访问，不暴露公网端口，不持有数据库凭据，不主动出网；一次处理一个任务，限制单文件大小、页数、运行时间、并发和临时空间，临时原文/转换件/OCR 文本任务完成后清理。
- OCR 提取的银行流水行先进入来源/对账待确认状态；每笔日期、收付方向、金额、对方、摘要均须财务人员核对后才能认领。OCR 结果不直接成为 Payment 或正式收入。
- 数字版 PDF 尽量先提取原有文字层；扫描页再 OCR。为人工逐笔核对保留页码和 Tesseract TSV/hOCR 行框坐标；OCRmyPDF 的文字层仅用于检索/预览，不能把文本顺序当作银行表格列结构。任何 OCR 置信度不得被解释为账务确认。

### 3.3 按来源的落库口径

| 来源 | 导入结果 | 不自动执行 |
| --- | --- | --- |
| 银行流水 CSV/XLSX/PDF | 保留原件；解析为待认领来源行；记录账期、来源批次和行指纹 | 不因对方名称/金额自动确认案件收款或费用 |
| 工资表 XLS/XLSX | 按映射解析期间与已支持薪资字段，作为 `NEEDS_REVIEW` 工资导入记录；逐人复核 | 不把申报工资推定为实付，不把空白推定为零，不按姓名自动绑定 User |
| 花名册 XLS/XLSX | 要求明确截至日，人员行待复核/待关联 | 不新建或修改员工账号，不根据同名自动关联 |
| 外部会计三表 XLS/XLSX/PDF | 识别报表名称、科目/项目、期间和金额，作为待复核核对记录 | 不生成法定凭证、不覆盖 LawLink 经营口径、不替代外部会计判断 |
| 案件登记/合同清单 | 只读暂存并生成按所内案号/合同号的差异核对结果 | 不自动创建 Matter、客户、Billing、Invoice 或 Payment |
| 无法识别的其他文件 | 私有原件归档并展示失败/不支持原因 | 不把 OTHER 计作类型化导入或会计事实 |

字段映射须可在预览中修正，并保存可复用的字段名映射模板，不保存原始敏感行样例。行级异常可被财务人员明确排除或修正；未处理错误不可让批次伪装成完整导入。

工资表、花名册来源姓名只保存在 `FinanceImportRecord`，供已有 `finance.read` 权限范围内的人工核对；不根据同名自动关联账号。预览姓名继续掩码显示。类型化记录去重指纹使用 `STORAGE_ENCRYPTION_KEY` 域分隔 HMAC，包含姓名（如适用）与业务字段，不含工作表或来源行号；不得使用可被字典反查的普通 SHA-256 姓名摘要。

## 4. 财务工作区

### 4.1 资金经营总览

- 复用 `getInternalFinanceSummary`、已提交计算快照、月结状态和已有成本/税款/个人余额事实，不复制计算公式。
- 按期间区分正式确认的律师费收入、律所留存、律师分配、已登记成本/经营结果、个人预存与税款预付，以及待认领来源行/缺失成本覆盖。
- 无正式计算批次时显示“尚无已确认快照”；缺少成本、报表或来源时显示“待核对/未登记”，不能以零代替未知，也不能把案件标的额当收入。
- 银行导入额、已认领收款、已开票金额和会计老师三表分开展示，避免重复累加或口径混淆。

### 4.2 律师个人结算包

- 依据指定 `COMMITTED` 计算批次生成“一名律师一份 XLSX + 汇总 ZIP”；文件标明期间、计算批次、来源指纹与待复核事项。
- 只导出该批次中确认归属的该律师金额、项目/分配构成、成本承担、预存双余额及核对差异；未确认来源与全所其他律师明细不得混入个人文件。
- 全所批量包仅开放给现有全局财务导出权限；其他用户只能访问已有授权范围，不能通过改 URL 或传入他人 ID 扩权。
- 报表必须可追溯到原有正式计算快照，不从导入草稿重算或自行改变分成规则。

### 4.3 往来单位流水透视

- 以银行来源行的对方名称指纹为维度，提供期间、收/付方向、待处理状态筛选和分页；名称相近但指纹不同者不擅自合并。
- 明确区分“银行来源金额（含待认领）”与“已确认案件收款/正式分配”，同一笔资金不跨口径重复计入。
- 仅按财务权限读取；姓名/账号/摘要等敏感字段延续现有展示与下载权限，普通律师不获得全所对方单位列表。

### 4.4 财务企微摘要

- 新增独立财务发送开关，默认关闭；配置 webhook 时不回显密钥，并由管理员填写可识别的目标群名称。
- 每次推送先展示目标群标签、期间与完整消息预览；仅在授权财务人员再次确认后发送，不设置自动推送或无人值守重试。
- 默认消息仅包含月结状态、阻断事项数量、系统内查看提示；不含客户/案件名称、个人工资/分配金额、银行账号、Webhook、公开下载链接。
- 发送成功/失败写审计，不把 webhook URL 或完整敏感请求体写普通日志。若系统当前 webhook 设施不满足上述要求，则先补安全存储与审计，不复用不安全的明文设置。

## 5. 权限与隐私

- 所有页面/API/导出均在服务端执行 `finance.read`、`finance.import`、`finance.export` 对应权限检查；UI 隐藏不是权限控制。
- 财务全局明细、批量个人包、往来单位透视和企微推送需全局财务权限；个人范围只返回本人允许看到的记录。
- 导入预览中的姓名、账号和摘要遵循现有脱敏逻辑；原件下载需独立授权并审计。
- 预处理工作者输入只来自系统私有上传；拒绝路径穿越、伪造扩展名、超限文件与恶意 PDF；清理临时文件并对失败作审计但不记录原文。

## 6. 交付与验收

### 自动化验收

- 使用合成 XLS/XLSX/CSV/PDF 覆盖多表头、尾部空格式列、期间歧义、重复指纹、OCR 误读、加密/损坏 PDF、越限文件和临时文件清理。
- 验证工资/花名册/外部三表进入正确类型且 `NEEDS_REVIEW`；银行导入只创建待认领来源，不直接创建收款事实；案件清单只产生差异报告。
- 验证既有归档批次保留、相同 `(hash, kind)` 不重复写入、事务回滚完整、审计可追踪且日志不含敏感原文。
- 验证正式批次、个人包、往来单位透视、经营总览各自的权限隔离、期间边界、金额合计和未知值展示。
- 验证企微开关初始关闭、未配置不能发送、预览和二次确认必需、普通角色不能发送，失败不会自动重试。

### 真实资料与部署验收

- 先在本地/170 预览真实资料，记录每个来源的解析行数、错误、账期及重复判断；经财务确认后才提交待复核批次。此前归档批次仍可追溯。
- 真实源行只用于本次受控验收，不复制进测试夹具、Git、截图或无权限日志。验收报告对外只报告文件/批次数量、行数、状态和错误类型，不展示客户、员工、金额或银行账号。
- 部署前备份 170 数据库与附件存储，核验恢复点；先部署隔离工作者并做资源/本机健康探测，再部署应用，执行数据库迁移（如有）、权限与真实预览测试。
- 外部请求与登录页端到端确认、日志检查、备份可恢复性通过后才报告部署完成；失败时按发布版本回滚应用并保留已安全提交的追加批次，不删除审计来源。

## 7. 回滚

- 代码发布回滚至先前镜像；OCR/转换工作者可独立停用，原有财务页面/导入继续可用。
- 新导入批次与原始附件采用追加式留痕。误导入且尚未被复核/计算引用的批次由财务管理员按系统撤销流程标记；已有正式快照引用的数据只能以追加更正/冲销处理，不覆盖原来源。
- 不提供“清空所有真实数据”的自动回滚脚本，不因新功能失败删除此前 OTHER/银行归档批次。
