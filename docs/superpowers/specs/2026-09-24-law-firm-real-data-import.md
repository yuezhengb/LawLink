# 律所真实资料导入设计

## 目标

在现有 LawLink 财务域上，将本所提供的真实资料按资料类型安全归档并进入可复核状态：银行流水进入银行来源与对账队列；工资、花名册和外部三表进入各自的类型化导入记录；原始文件保留在受控私有存储；任何不确定的人员、期间或承担口径都停在人工复核，不自动入账。

本次真实导入只用于本所内部预览和后续复核，不进入 GitHub、测试夹具、普通日志或公开下载地址。

## 资料分层

| 资料 | 首次动作 | 不自动做的事 |
| --- | --- | --- |
| 银行流水 | 预览、去重、按账期归档，生成待认领对账行 | 不把无法确定的收款强行关联案件 |
| 工资表 | 原件归档；字段完整且期间明确的行进入待复核记录 | 不把“申报工资”推定为实际支付，不把空白承担项推定为零 |
| 花名册 | 按截至日归档，生成待人工关联的人员行 | 不按姓名首个匹配结果修改 User |
| 外部三表 | 生成资产负债表、利润表、现金流量表核对行 | 不生成法定凭证，不替外部财务老师确认会计口径 |
| 案件/合同登记表 | 在来源文件可用且字段映射确认后做只读差异匹配 | 不凭合同号或客户名称创建不存在的 Matter/客户 ID |

## 当前资料启用顺序

1. 银行流水：先导入 9 份已标准化 CSV；相同文件指纹只产生一个正式批次。
2. 外部三表：导入 4 个账期的标准化核对文件，保持 `NEEDS_REVIEW`。
3. 花名册：导入可识别的在册表，要求提供明确截至日，全部待人工关联。
4. 工资：先修正 Excel 空尾列读取并逐表预览；文件标题与文件名期间不一致时只归档/待复核，不静默选定期间。
5. 案件登记表：当前主来源缺失时只保留可追踪的受控原件，不伪造案件主数据。

## 提交闸门

- 预览必须返回行数、错误数、期间和类型；任一行解析错误时，该批次不写正式业务事实。
- 提交前按文件 SHA-256 与资料类型去重；重复提交返回原批次，不重复写入。
- 银行资料写入 `FinanceSourceRow` 和 `FinanceReconciliationCase`；非银行资料只写 `FinanceImportRecord`。
- 原始文件写入私有存储并记录来源文件、操作者和审计事件。
- 工资/花名册需要财务人员逐条或逐人复核后才进入正式工资事实或人员关联；外部三表只标记核对状态。
- 任何真实数据导入完成的表述必须有系统界面/API 预览、批次记录和数据库计数三份证据；无法访问 VPS 或没有有效认证会话时，不能声称已经导入。

## 回滚与验收

导入前保留数据库与私有附件备份；批次提交采用事务，失败时清理附件路径。若批次内容或口径需要撤销，使用追加更正/冲销或删除尚未启用的导入批次，不覆盖原始来源。

最低验收：

- 解析器不会因 Excel 仅有格式的超宽空尾列变慢或产生空数据列；
- 9 份银行标准化来源和 4 份外部三表预览无解析错误；
- 银行重复文件不增加第二批次；
- 非银行资料不产生银行对账行；
- 工资期间冲突、空金额和人员未关联状态在页面可见；
- VPS 上能看到批次、来源类型、行数、状态和审计记录；敏感原始值不出现在 Git 或普通日志。
